# 公允价值算法 v2 — 多年归一化估值方法论

> 适用范围：`frontend/src/lib/data/` 下的估值管线，即网页 Dashboard 与告警（Alerts）共用的同一套算法。

---

## 1. 问题定位

### 1.1 触发场景

用户报告的页面输出（用户提供，本次会话**未能**连线行情源复核，见 §6）：

| 字段 | 页面值 |
|---|---|
| 现价 | $648.03 |
| 分析师目标均值 | $758.28 |
| 分析师目标区间 | $580.00 – $1000.00 |
| Forward P/E | 18.5 |
| PEG | 0.86 |
| DCF 公允价值 | **$133.95** |
| 偏离度 | **+383.8%** |

同一标的在第三方（Morningstar，用户提供）的 Fair Value 为 $850。

### 1.2 内部矛盾

公允价值 $133.95 意味着该股票以 **约 4.8 倍**于其内在价值交易。但同一份数据里 Forward P/E 18.5、PEG 0.86——这两个数字描述的是一家**估值温和的成长股**。一套自洽的估值体系不会同时输出这两种结论。所以 $133.95 不是"保守"，是**算法错误**。

### 1.3 根因（旧代码）

旧管线的全部模型都由 3 个标量驱动，且这 3 个标量都取自**最近 12 个月的快照**：

| 标量 | 旧来源 | 失效方式 |
|---|---|---|
| `freeCashflow` | `financialData.freeCashflow`（TTM） | FCF = 经营现金流 − 资本开支。公司把资本开支翻倍去建数据中心时，经营现金流照样增长，FCF 却塌陷。永续模型把这个**低谷值资本化到永远** |
| `eps` | `defaultKeyStatistics.trailingEps` | 一次性费用（诉讼和解、一次性税费、减值）压低 TTM EPS，Graham Number / Graham 公式 / Lynch / EPV **四个模型同时**被拉低 |
| `earningsGrowthRate` | `financialData.earningsGrowth`（最近一期同比） | 同一笔一次性费用让单季同比变成深度负值，被 clamp 到 −10% 后**复利十年** |

因为所有模型共用这 3 个被污染的输入，"多模型平均"提供不了任何分散化——它们是一起错的。

三个次级放大器：

1. **权重结构**：核心两阶段 DCF 占 50%，剩余 50% 由其余模型**均分**——包括 Graham Number（1930 年代防御型选股的筛选线）和 EPV（零增长假设）。这两个天然的"下限指标"因此拿到了与现金流模型同量级的权重。
2. **离群值过滤器失效开放（fail-open）**：过滤器锚定在分析师目标区间上；一旦所有模型值都被判定为不可靠，代码回退到「对**全部**值取平均」——包括刚刚被判定不可靠的那些。守门员在最需要他的时刻离场。
3. **固定折现率**：所有股票一律 10% 折现率 / 2.5% 永续增长，与该企业现金流的历史稳定性无关。

## 2. 新算法结构

```
行情快照 (yahoo.ts)  ─┐
多年年报 (history.ts) ─┼─→ normalize.ts ─→ dcf-models.ts ─→ aggregator.ts ─→ 页面 / 告警
第三方数据 (fmp/av)   ─┘   归一化输入        10个估值模型      权重+离群+置信度
```

新增两个模块：

| 文件 | 职责 |
|---|---|
| `src/lib/data/history.ts` | 抓取最多 10 年年度财报（Yahoo `fundamentalsTimeSeries`，FMP 为备份） |
| `src/lib/data/normalize.ts` | 把 TTM 快照转换成"穿越周期"的输入，并输出可审计的调整说明 |

> 技术注记：`quoteSummary` 的 `cashflowStatementHistory` / `incomeStatementHistory` / `balanceSheetHistory` 三个子模块自 2024 年 11 月起基本返回空数据（yahoo-finance2 在运行时会打印该警告）。多年历史必须走 `fundamentalsTimeSeries`。

## 3. 归一化规则

### 3.1 自由现金流

取以下 4 个候选值的**中位数**：

| 候选 | 计算 | 作用 |
|---|---|---|
| TTM 实际 FCF | 直接取值 | 锚定现实 |
| 全周期利润率 | `median(FCF/营收, 最多8年) × TTM营收` | 熨平投资周期 |
| 近期利润率 | `median(FCF/营收, 近3年) × TTM营收` | 反映当前经营状态 |
| 股东盈余 | `TTM经营现金流 − 维持性资本开支` | 剔除扩张性投资 |

**维持性资本开支** = `min(TTM实际资本开支, max(折旧摊销按营收缩放, 历史资本开支强度中位数 × TTM营收))`

逻辑链条（为什么 A 导致 B）：扩张性资本开支买的是**未来**的盈利能力；把它从**今天**的现金流里全额扣除、再把扣除后的结果按永续增长资本化，等于对同一笔支出收费两次。所以维持性口径才是永续模型该用的分子。`min()` 保证模型永远不会假设维持性开支**高于**公司实际花掉的钱。

**护栏**：
- 归一化 FCF ≤ TTM 经营现金流（算术上限）
- TTM FCF > 0 时，归一化值被限制在 `[0.75×, 2.5×]` TTM FCF 区间内

### 3.2 制度转换守卫（Regime Guard）——最关键的一条

把当期被压低的利润率替换成多年中位数，在"这是周期/投资期"时是**对的**，在"这家公司就是在变差"时是**错的**。

判定规则：比较**近 3 年**与**前半段**的利润率中位数。

| 判定 | 条件 | 处理 |
|---|---|---|
| 持续下行 | 近3年 < 前半段 × 0.8 | **丢弃**全周期中位数候选，只用近期水平平滑 |
| 持续上行 | 近3年 > 前半段 × 1.25 | 同样丢弃全周期中位数（避免把改善中的公司往下拉） |
| 稳定 | 其余 | 使用全周期中位数 |

**资本开支高峰会抑制"持续下行"判定**——因为此时 FCF 利润率压缩的原因是投资决策，不是经营恶化。这正是区分「META 式资本开支周期」与「真实基本面衰退」的那条线。

### 3.3 每股收益

候选中位数：TTM EPS、`Yahoo trailing normalizedIncome / 股数`、`中位数净利率 × TTM营收 / 股数`。

`normalizedIncome` 是 Yahoo 已剔除一次性损益的口径——这直接对应 §1.3 表格的第二行。护栏：`[0.7×, 2.0×]` TTM EPS。同样受 §3.2 制度守卫约束。

### 3.4 增长率

**一个来源一票，取中位数**：

1. 营收 CAGR（最多 5 年，端点做两期平滑）
2. 归一化净利润 CAGR
3. 自由现金流 CAGR
4. 分析师长期（+5y）增速预期
5. 最近一期盈利同比
6. 最近一期营收同比

CAGR 仅在首尾两端**均为正**时计算（跨越符号变化的 CAGR 在算术上无意义）。端点采用两期平均，避免某一个特别强/弱的起始年份决定整条趋势线。

最终限制在 `[-5%, +25%]`。只有单一来源时打 7 折（缺乏交叉验证）。

具体例子：一笔一次性税费让"最近一期盈利同比"变成 −42%。旧算法直接把 −42% 拿去 clamp 成 −10% 再复利十年。新算法里它只是 6 票中的 1 票，中位数落在其余 5 个来源上，不受影响。

### 3.5 折现率（随波动率浮动）

```
折现率 = 9% + clamp(波动率, 0, 1) × 4%  [+ Beta 调整] [+ 数据不足加价]
波动率 = max(FCF利润率变异系数, 净利率变异系数)   // 变异系数 = 标准差/|均值|
限制区间 [8.5%, 13%]
```

为什么波动率该进折现率：折现率是**要求回报率**。一家利润率年年波动 ±50% 的企业，其未来现金流的预测误差远大于一家波动 ±5% 的企业；承担更大的预测误差就应当要求更高的回报。变异系数是无量纲的，所以 25% 利润率的软件公司和 3% 利润率的零售商可以直接比较。

永续增长率：默认 2.5%；波动率 > 0.6 降至 2.0%；归一化增长率 ≤ 0 降至 1.5%。

## 4. 模型权重重构

权重反映的是**"该模型对持续经营企业价值的证据强度"**，不是"该模型有多保守"。

| 模型 | 新权重 | 旧权重（约） |
|---|---|---|
| 两阶段 DCF（归一化） | **26%** | 50% |
| 10年 FCF DCF（增长衰减） | 13% | ~5.6% |
| 保守 FCF DCF（下行情景） | 10% | ~5.6% |
| 第三方 DCF（FMP，全部共享） | 10% | ~5.6% × N |
| EV/EBITDA | 9% | ~5.6% |
| 剩余收益模型 RIM | 8% | ~5.6% |
| 5年 FCF DCF | 8% | ~5.6% |
| 盈利能力价值 EPV | 7% | ~5.6% |
| 格雷厄姆内在价值公式 | 5% | ~5.6% |
| 股息折现 DDM | 5% | ~5.6% |
| Lynch (PEG=1) | **2%** | ~5.6% |
| 格雷厄姆数字 | **2%** | ~5.6% |

两处关键调整：

- **格雷厄姆数字 5.6% → 2%**。它是 1930 年代为防御型投资者设计的**筛选阈值**（"低于此价才值得看"），不是估值模型。对轻资产企业它天然给出极低的值。让它以接近现金流模型的权重参与平均，等于系统性地把公允价值往下限拽。
- **第三方 DCF 合并为一个 10% 桶**。FMP 会返回 4 个高度相关的 DCF 值；按原逻辑它们各自独立计权，合计可达 22%，一个数据源就能压过全部内部模型。

模型结构本身也改了两处：
- 两阶段 DCF 从「10 年平增长 + 断崖式跌到 2.5%」改为「5 年增长 + 5 年线性衰减至永续」。断崖恰好落在价值最集中的位置。
- 剩余收益模型的超额收益（ROE − r）改为 8 年线性衰减，而非"5 年恒定后归零"。超额回报会吸引竞争，这是衰减的经济学理由。

净现金桥：Yahoo/FMP 的 FCF 是**杠杆后**口径（经营现金流已扣利息），所以折现结果本身就是股权价值，**不再扣减债务**；但净现金是现金流几乎不产生收益的资产，予以加回，上限为经营现值的 20%（防止资产负债表数据异常主导估值）。

## 5. 离群值守卫与置信度

### 5.1 两级过滤（不再 fail-open）

1. **绝对合理性**：剔除 `< 0.2×现价` 或 `> 5×现价` 的值。区间故意放得很宽——这一级只抓**数据错误**（ADR 股数比例错、货币混淆），不做价值判断。
2. **稳健离散检验**：MAD（中位数绝对偏差）× 1.4826 作为标准差等价量，剔除偏离中位数 3.5 倍以上的值（模型数 ≥ 5 时启用）。
3. **保底**：若存活值少于 3 个，保留**离中位数最近的 3 个**——而不是回退到"用全部值"。

### 5.2 置信度与区间

输出新增 `valuation_quality` 字段：

- `dispersion` = `(P75 − P25) / 中位数`，衡量模型之间的**一致程度**
- `fair_value_low` / `fair_value_high` = 可靠模型值的 P25 / P75
- `confidence`：
  - `high`：≥5 年历史 且 ≥5 个模型入选 且 离散度 < 0.45
  - `low`：<3 年历史 或 <3 个模型入选 或 离散度 > 1.0
  - `medium`：其余

置信度衡量的是**模型之间是否互相认同**，不代表估值正确。页面文案已按此措辞。

### 5.3 前端透明化

`DCFDetailTable` 新增"估值输入归一化"面板，逐项展示：

- 每个输入的**报告值 vs 模型采用值**（FCF / EPS / 增长率 / 折现率）
- 历史波动系数
- 每一条调整的文字说明（例如："检测到资本开支高峰：当前 capex/营收 28.0%，历史中位数 12.0%"）
- 模型表新增**权重列**（按实际入选模型重新归一化，合计 100%）

## 6. 验证

### 6.1 数据源可达性限制

本次会话的出口网络策略**拒绝**了全部行情域名（`query1/query2.finance.yahoo.com`、`fc.yahoo.com`、`financialmodelingprep.com`、`www.alphavantage.co` 均返回代理 403）。因此**无法**用任何真实股票的实际财报数据端到端验证，也**不会**在本文档中给出任何具体股票的新公允价值数字。

§1.1 的数字全部来自用户提供，未经本次会话独立核实。

### 6.2 合成场景自测

`frontend/scripts/valuation-selftest.ts`（`npm run valuation:selftest`）用**人工构造**的财报形态验证算法行为。以下数字是合成的测试夹具，不是任何真实公司的数据。

| 场景 | 构造 | 断言 | 结果 |
|---|---|---|---|
| A 资本开支高峰 | 资本开支强度 12% → 28%，利润率不变 | 识别 capexSpike；归一化 FCF > 1.3× TTM；公允价值 > 1.2× 仅用 TTM 输入的结果 | 仅TTM $421.62 → 归一化后 **$751.37** |
| B 一次性费用 | 报告净利率腰斩，`normalizedIncome` 不变，单季同比 −42% | 归一化 EPS > 1.2× TTM EPS；增长率不被 −42% 主导 | EPS 13.80 → **27.60**；增长率 −42% → **+17.5%** |
| **C 真实经营恶化（负向对照）** | 利润率 6 年单调下滑，资本开支正常 | 归一化**不得**把 FCF 拉高超过 25%；增长率为负 | FCF 9.6B → **9.6B（零上调）**；公允价值 $36.74 → **$33.76（下调）** |
| D 稳定复利机 | 波动系数 0.02 | 折现率 ≤ 9.5% | **9.1%** |
| E 强周期股 | 波动系数 0.90，单季同比 +90% | 折现率 ≥ 10.5%；增长率不被 +90% 主导 | 折现率 **12.6%**；增长率 **+11.2%** |

场景 C 是最重要的一条：它证明新算法**不是一个普遍抬高估值的补丁**。同样的归一化逻辑，在资本开支周期下把公允价值抬高 78%，在真实衰退下把它**压低**。

## 7. 其他改动

`frontend/src/app/api/alerts/check/route.ts` 改为直接调用 `getFullValuation()`。此前它请求一个独立的 Python 服务（`backend/`），而该服务的 DCF 是单一硬编码假设模型（"10yr, 8% growth, 10% discount"）+ 简单平均——告警可能基于用户在页面上**从未见过**的公允价值触发。

`backend/` 目录下的 Python 估值逻辑现已不被任何前端路径调用。

## 8. 已知限制

- 归一化护栏（FCF `[0.75×, 2.5×]`、EPS `[0.7×, 2.0×]`）是**建模假设**，不是从数据推导出的参数。它们的作用是防止归一化把公司改写成另一家公司。
- 净现金加回的 20% 上限、EV/EBITDA 的 12× 乘数同属建模假设，均已在代码中命名为常量并注释。
- 制度转换的 0.8 / 1.25 阈值同上。
- Yahoo `fundamentalsTimeSeries` 对部分 ADR 与小市值标的的历史深度不足；不足 4 年时回退 FMP，仍不足则 `confidence` 降为 `low`。
- 本算法未做行业调整：EV/EBITDA 对全部行业使用同一个 12× 乘数。
